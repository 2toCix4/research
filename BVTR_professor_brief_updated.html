기존 BVTR · 보고된 결과

질문 적응형 토큰 교체

질문이 달라졌을 때 일부 시각 토큰을 교체하면서 캐시 크기를 유지합니다. GQA Shift3에서 Fixed288보다 높은 두 후속 질문 동시 정답률이 보고됐습니다.

소스 정적 감사로 확인

불필요한 계산 및 복사 구간 식별

Sparse 계산은 신규 query row만 처리하지만, 유지 KV를 새 캐시로 옮기는 메모리 복사는 발생합니다. 원본 경로 간 초기 dense 계층 수 차이도 확인했습니다.

신규 연구 가설

예산 인식형 갱신(BQAR)

질문 변화의 크기에 따라 교체량뿐 아니라 실제 재계산 query 수도 동적으로 조절해 비용을 절약하는 접근을 검토합니다.

효과 미검증

깊은 KV 상태 예측

깊은 계층의 일부 상태를 작은 예측기로 근사하는 실험을 진행했습니다. CPU 극소 표본에서는 정확도 차이 없이 실행시간이 더 길었으며, GPU 이점은 아직 확인되지 않았습니다.

종합 장단점 및 한계

교수님 질의에 대비한 정리

연구의 장점

  • 고정된 활성 토큰 예산에서 질문 변화에 대응한다는 문제가 명확합니다.
  • 기존 GQA 500개 평가 결과로 Fixed288 대비 개선을 관찰했습니다.
  • 이전 캐시를 재사용하는 방식과 새로운 갱신 정책을 분리해 분석할 수 있습니다.
  • Codex 정적 감사로 기존 구현의 숨은 계산 비용과 비교 오류를 발견했습니다.

핵심 한계

  • 새 BQAR의 실제 정확도 및 GPU 지연시간은 미검증입니다.
  • Teacher layer16 scorer 자체가 비쌀 수 있습니다.
  • Full576 정상 KV 재사용 기준선과의 공정 비교가 필요합니다.
  • KV 복사, Replay, Python 호출 비용이 계산량 절약을 상쇄할 수 있습니다.
  • 기존 BVTR 논문과의 기여 중복 및 관련 연구 신규성 검토가 필요합니다.

우선순위별 다음 실험

결과를 보고 다음 단계로 넘어가는 검증 계획

  1. 원본 경로 재현: 추가 의존 모듈을 반영하여 GQA Sparse48 added-only/early0 계산 경로를 정확히 확인하고 동등성 테스트를 수행합니다.
  2. 정확도 게이트: 동일 selector·동일 생성 조건에서 Sparse48 대비 BQAR 정확도 손실을 검증합니다.
  3. 연산량 게이트: BQAR의 교체 수 감소가 실제 deep query row 감소로 이어지는지 로깅합니다.
  4. GPU 시스템 평가: Selector / Refresh / Replay / Answer 별 지연시간, 전체 E2E, Peak VRAM을 각각 측정합니다.
  5. 강한 기준선: Fixed288, Sparse48, Sparse96, Dense288, Full576 정상 KV 재사용을 같은 조건에서 측정합니다.
  6. 독창성 판단: 비용 대비 성능 이득과 선행연구 차별성을 종합해 BQAR 유지·수정·폐기 여부를 결정합니다.

연구 현황 및 채택 가능성

실험 근거와 아직 해결되지 않은 검증 과제

연구 현황

기존 BVTR에서는 고정된 288개 시각 토큰을 유지하는 방식보다, 질문이 바뀔 때 최대 48개를 교체하는 방식이 GQA Shift3에서 높은 동시 정답률을 보였습니다(40.6% → 46.6%). 그러나 정적 코드 감사 결과 실제 계산 경로의 차이와 캐시 복사 비용, Teacher selector의 추가 비용이 확인됐습니다. 후속 연구에서는 질문별 갱신 필요성에 따라 재계산량을 조절하는 BQAR을 검토하고 있습니다. 현재 구현 및 CPU 테스트 일부를 진행했으며, 핵심 GPU 정확도·지연시간 실험은 아직 수행하지 않았습니다.

상향 판단 조건: BQAR의 신규 기여 입증, 동일 조건의 강한 기준선 비교, 독립 데이터셋 성능, 실제 GPU 시간·메모리 이득 확인.

추가 검증이 필요한 항목

  • BQAR의 계산 절약이 실제 GPU E2E 지연시간 감소로 이어지는지
  • 일반 Full576 KV 재사용 등 강한 기준선과 공정하게 비교했는지
  • 기존 BVTR과 새 연구가 충분히 구분되며 중복 제출 문제가 없는지
